# ArchitectureWeb.Page

## Purpose and Scope
Own page for [ArchitectureWeb](../DESIGN.md). No child components.

## Responsibilities and Boundaries
Render the shared local page through SwiftHTML and own browser presentation state. Authentication and source authority remain in the server and daemon; this component consumes their public contracts.

## Contracts and Invariants
Rendered labels and signatures are plain text. Browser state belongs to the page event loop; source is obtained through authenticated Client requests. View invalidation never resets the user transform unconditionally. Server-side session/task ownership is defined by the Web package contracts.

The shared renderer uses a native desktop utility layout: a 44 px application toolbar, a 36 px canvas toolbar and a 32 px filter row. System typography, compact controls and neutral panels prioritize usable canvas area. Navigator and Inspector scroll independently; the viewport does not scroll. Responsive layouts may reduce secondary labels, while keeping primary actions and a usable canvas. The standalone export uses the same renderer and density.

The Canvas status bar toggles a read-only Terminal drawer below the drawing area. A new page starts collapsed. The page owns a bounded, timestamped history of observed view loads, diagnostics, index and connection events, and verification status. History is retained across navigation in the tab, including while the drawer is closed. The drawer uses text only and receives event summaries, without serializing request payloads. Opening it uses the existing Canvas resize path. Errors mark the toggle until opened; the History command opens the drawer to show its requested comparison.

The application toolbar keeps search, index status and one More actions button. Its native popover groups the canvas switcher, file commands, extensions and export. Repository mode hides the launcher when those commands are unavailable.

The live-index indicator confirms a connection on the first authorized data event. A terminal subscription error is shown and logged once and leaves the last loaded graph visible. Transport interruptions may reconnect and refresh on the next index event, keeping the existing snapshot pins and imported canvases.

The live source footer shows the canonical workspace root from the authenticated host session, independently of the current view and snapshot. The path uses selectable text and keeps its full value in the tooltip when space is limited. Saved HTML does not include the local root path.

The canvas toolbar keeps 12 px inline gutters at every width. A two-column grid gives the title the remaining space; title/breadcrumb text truncates before it can overlap the hierarchy selector or view toggle. Back and the toggle retain their hit areas, while the selector may shrink on very narrow canvases. Both List view and Graph view labels must remain wholly inside the toolbar with the trailing gutter, including at the 320 px desktop canvas minimum.

Navigator and Inspector widths belong to the page session and survive query, live-data and theme changes. CSS owns responsive default widths. Eight-pixel separator hit regions support primary-pointer capture, Left/Right keys (8 px, or 32 px with Shift), Home/End bounds, and double-click default reset. Sidebar bounds are 160–400 px and Inspector bounds are 200–480 px, further constrained by the other panel and the available workspace. The canvas reserves 320 px, or 55% of the workspace below that size budget. At the existing narrow breakpoint the Sidebar and its separator are hidden; the Inspector remains adjustable, with its minimum reduced only when the viewport cannot accommodate 200 px. Viewport shrink constrains Inspector preference first and then Sidebar; manual adjustment holds the opposite panel at its effective width. Separator ARIA values always report effective pixel widths and current bounds. Reload uses responsive defaults; no persistence or server request is introduced.

```text
Pointer down -> capture -> latest pending width (one animation frame)
                                 -> clamp -> grid widths + ARIA -> canvas resize
Pointer up / cancel / lost capture -> flush -> release and clear drag state
Keyboard / reset / viewport resize -> clamp -> grid widths + ARIA -> canvas resize
```

A toolbar sidebar icon button toggles Navigator visibility for the page session. Its action label/title changes between Hide sidebar and Show sidebar, with `aria-controls` and `aria-expanded` reporting the controlled pane and effective visibility. The two directional icon states remain available outside the pane. Hiding removes the pane and its separator from layout/focus and sets its grid width to zero; reopening restores the preferred width within current bounds. Finishing an active resize before hiding flushes its latest width and releases pointer capture. Visibility survives query/history/live-data/theme changes without a request or graph layout. Reload uses the responsive default. At the existing narrow breakpoint the sidebar remains automatically hidden and the button is disabled with an explanatory title; widening restores the session preference. Both live and standalone views share this behavior.

```text
Toolbar icon -> finish pending resize -> toggle session visibility
    -> pane + separator + grid width + ARIA -> existing canvas ResizeObserver
```

The page event loop owns sidebar visibility, preferred widths, the active pointer and the single pending animation frame. All termination paths clear capture/drag state. Grid resizing never runs graph layout or Fit, and keeps graph coordinates, selection, pan and zoom. Both live and saved views observe their graph container so resizing updates Cytoscape's actual drawing area. Canvas toolbar/filter density follows its actual column width through a CSS container query, keeping filter controls usable when the side panels are expanded.

Appearance follows `prefers-color-scheme`. The same media query selects an explicit `color-scheme: light` or `dark` for native controls, alongside the page tokens. Select options and groups have explicit menu background/text colors so native or browser-rendered pickers cannot inherit light text over an unspecified background. Selection, keyboard navigation and change events remain native. Light and dark tokens use neutral surfaces; node kinds use labeled semantic accent marks, with semantic language and relation accents defined below. A media-query change updates the Canvas renderer's palette without recreating the graph, moving nodes, changing selection or resetting pan/zoom. Theme changes require no server request or persisted preference.

Edges use semantic color on both the line and arrow instead of persistent small text: neutral containment, blue dependencies, teal calls, purple references, amber design membership, and indigo control flow. Only recorded `controlFlow` facts with `cfg.branch` equal to `true` or `false` receive the green/orange branch colors. Candidate calls and semantic references retain dashed lines; false branches are dashed as a second cue. Unknown relation kinds remain explicitly Other with a dotted neutral line and their exact kind in textual details. The Relations legend lists the categories and line patterns in the current graph. It stays in the lower-right corner of the canvas viewport when the navigator closes or the graph moves. Pointer input passes through to the graph. List view displays the same cues on its relation rows. Exact kind, branch and endpoint names remain in the edge hover tooltip and the accessible List. Presentation never promotes a candidate to a definite call or infers branches from entity names. Overview edges are thin (1.2 graph units) and translucent context. Hovering a leaf node previews its incident edges; otherwise selected nodes (including descendants of explicitly selected frames) determine the focus. Focused edges use 1.8 units and full opacity; unrelated edges recede to 8% opacity. Edge hover/selection emphasizes that edge at 2 units. Pan and zoom clear transient node/edge hover previews while retaining persistent selection. Compound-frame hover alone never emphasizes the entire package. Leaving a preview restores the persistent selection, and clearing selection with Escape or a canvas-background click restores the overview and clears stale Inspector/navigation-row selection state. No node is faded and no recorded relation is removed. Semantic colors and line patterns are unchanged; both palettes retain at least 3:1 contrast at full opacity for focused reading. Live and saved HTML share these rules; theme changes preserve graph state.

Navigator rows, graph labels, list rows and Inspector badges display the [IR declaration refinement](../../../../../Sources/ArchitectureIR/Model/DESIGN.md) with an explicit coarse-category fallback. The UI does not interpret language-specific parser nodes or infer a paradigm from a symbol's name. Inspector shows the recorded source signature; language and declaration role remain distinct from the current graph level.

Nodes are neutral information cards: a distinct role badge and language in the header, a prominent name, an optional recorded declaration signature, and a source/owner footer. CFG boundaries explicitly display `cfg.synthetic`; they are not classified from their names. Source context comes from the recorded anchor or project manifest; missing context is stated. The accessible List repeats these attributes without truncation. Card text is XML-escaped before being embedded as an SVG image, and constrained to its text region; raw source never becomes SVG markup. The shared fixed-width geometry contract below is used by Cytoscape, the SVG and the layout model, including conversion from layout top-left coordinates to node centers. Card images are regenerated only on data or system-theme changes, not during pan/zoom. Selection retains a distinct native canvas border. Theme updates preserve positions, selection and viewport.

Role marks use the same recorded declaration refinement and coarse-kind fallback as their text labels. Class, struct, enum, actor, interface, function, method, value, constant, alias, scope, package, module, file, extension, flow and unknown/external roles map to explicit Light/Dark accent tokens. A 20 × 20 tile carries a 14% accent tint, an accent outline and a full-opacity glyph with at least 4.5:1 contrast against the composited tile. Color is an additional cue; the role name and distinct glyph remain visible. No role is inferred from names or languages.

SVG marks position one- and two-character glyphs at the tile center with middle text anchoring and a central dominant baseline. Navigator and List marks use the same role mapping, a fixed 20 × 20 grid and centered inline contents. The Inspector's role label uses the same accent, while its language label stays separate. Neutral card/panel backgrounds, card/layout geometry, language logos and relation colors retain their existing contracts. System-theme changes update mark accents without moving nodes or resetting selection or viewport; saved HTML shares the same assets.

Source and repository card headers share one language mark renderer. A producer records the language of a declaration or reference at its source site. Canvas JSON preserves an optional language independently of the role. Language aliases share one mark. Bundled Swift, Rust, TypeScript, JavaScript, Python, Go, Kotlin, C, C++ and Terraform vectors require no runtime downloads. Other named languages use a centered monogram with their full accessible name. Language-neutral entities retain their own role mark. Swift keeps its white bird on orange; Rust keeps the gear's negative space. Compact source property rows and specialized diagram geometry retain their own presentations.

### Browser navigation

The browser History API is the single navigation owner for live views. Hierarchy changes, scope expansion, neighbors/impact/CFG actions, filter changes and pagination push an entry; identical queries do not. The first debounced search pushes an entry and further edits within that search replace it. The page's Back button calls browser Back and is disabled at the first application entry. Browser Back/Forward restore the exact query, hierarchy selector, filters, search text, List mode and available entity selection. Entering a new route clears stale Inspector content. Returning to a completed graph restores its captured pan/zoom after layout; live refresh keeps its existing transform contract.

```text
View action -> capture outgoing entry -> push/replace browser state -> load query
Browser Back/Forward -> popstate -> restore controls -> load query -> restore viewport
```

Entries contain a versioned application marker, an application index, query and small UI state; graph/source payloads and authentication tokens are never stored in them. The initial entry uses replaceState after launch-token removal, so Back does not replay authentication. Reload restores a recognized current query. A cache of the latest 32 traversed UI states preserves outgoing viewport state during native traversal; older entries retain their browser-stored query and captured UI state. New navigation after Back discards the corresponding forward cache. Foreign history states are not interpreted as RPC requests. Unsupported saved-view navigation reports its existing explicit limitation and does not create live-query entries.

Navigation cancels pending search debounce and invalidates in-flight query/layout responses before loading the target. Restoration never pushes another entry. Failed requests keep a visible diagnostic and can be left with Back. Same-document navigation does not recreate the WebSocket or reauthenticate. Behavioral renderer tests own history ordering, restore controls, query races and saved-view isolation; real browser Back/Forward verifies the browser event path.

### Source syntax highlighting

Inspector declaration and source-preview blocks use the recorded Swift/Rust language with a pinned, bundled Highlight.js core and only those two grammars. No automatic language inference or runtime network request is used. The same grammar asset is embedded in standalone HTML for bundled declaration signatures; source bodies remain unavailable offline. Source content is escaped by the highlighter before insertion as its token-span markup; source text is never interpreted as supplied HTML. Original whitespace and copyable code text remain exact. Truncation notices are separate from tokenized source. Unknown languages use literal plain text. Missing grammars or highlighting errors retain literal source with a visible notice. Highlighting is limited to 16,384 UTF-16 code units per block; larger blocks remain literal with a visible limit notice. The authenticated source endpoint already bounds preview bytes to 16 KiB.

```text
Authenticated source / recorded signature + language
    -> bounded Swift/Rust grammar -> escaped token spans -> Inspector pre/code
    -> CSS syntax tokens -> system Light/Dark palette
```

Syntax tokens have at least 4.5:1 contrast against the neutral code surface in both palettes. Theme updates recolor existing spans through CSS without refetching, rerunning highlighting, or changing graph selection/camera. Highlighting completion stays inside the existing inspection request/selection guard, so abandoned source responses cannot append a stale preview.

### Compact property rows

Property/field entities, including constants and statics but excluding aliases/associated types, use 640 x 32 rows with access, binding, name and declared-type columns on one line. Property row content and property-frame summaries use 14 px text, with the property name in semibold. Rows have no repeated role header, language logo or source footer. A setter restriction appears alongside read access. Missing metadata is visibly unrecorded; a historical signature remains available in the row/tooltip and Inspector rather than being parsed to invent metadata. Text is escaped, bounded and measured; full signatures/source remain in List and Inspector. Row identity, hit-testing, selection, source access and recorded incident edges remain intact.

Within a scope, leaf property rows form a single contiguous source-ordered section above callable/type cards, with no per-row vertical gaps. A property that itself owns visible descendants remains a containing frame with a compact declaration summary in its header, retaining access/binding/type without restoring card chrome. The shared layout model owns all leaf dimensions; Cytoscape and workers use those exact sizes and centers. Geometry/order changes are included in topology keys. Views containing property rows compose scopes bottom-up: semantic facts between scope descendants project only onto immediate child boxes for placement; row-related and compound-boundary edges retain native curves between original endpoints. Direct non-row leaf relations retain ELK routes. Views without property rows retain the existing joint-compound layout contract. All facts remain in List and counts, and no presentation ordering becomes a recorded fact.

### Scope breadcrumbs

The compact canvas toolbar uses a semantic breadcrumb navigation instead of the generic visible heading and query-method text. Its screen-reader h1 retains the current scope/mode name. Workspace home opens the module overview. Each recorded ancestor opens its standard child scope; the current scope is not a link. CFG/neighbors/impact append their mode after the focused declaration. Ancestor navigation uses the existing History owner, clearing cursor/filters and preserving explicit snapshot pinning. Back/Forward and reload refetch the hierarchy without storing graph payloads in history.

Focused views make one separate `graph.neighbors` request pinned to the returned view snapshot, with incoming contains-only traversal, depth eight, at most 500 nodes/1500 edges. It does not change the active graph query, its counts, Canvas elements or layout. The unique most-specific recorded parent forms each step: a parent that is also an ancestor of another recorded parent is a redundant shortcut and is omitted from this presentation path. Original facts remain untouched. Ancestor closures are bounded by the 500-node response (at most 500 squared entries). Ambiguity, cycles, truncation, missing focus, snapshot mismatch and request failure are visible hierarchy notices, never guessed paths. If eight links end before a workspace root, the available suffix is explicitly partial. Request-generation guards discard stale hierarchy success/failure along with stale views. Pending navigation removes old active breadcrumb targets.

The home button and current item remain compact. At narrower canvas widths, middle ancestors collapse into a native ancestor picker; very narrow canvases also collapse the immediate parent. The picker always contains every loaded ancestor. Full names remain in titles/options, and every button uses a native keyboard hit area. The same system control colors apply. Saved exports show an explicitly disabled home and a Saved snapshot label, since their external hierarchy is not bundled.

### Graph layout

The shared layout model owns presentation hierarchy and placement for both live and offline HTML views. Unique recorded `contains` parents become compound frames for workspace, system, package, module, file, declaration and design-group entities. Ambiguous ownership remains an explicit edge; it never chooses an arbitrary parent. Containment represented by a frame is omitted only from Canvas arrows, while all facts remain in counts and the accessible List. CFG views stay flat and use only recorded control-flow edges as ordering constraints; function cards occupy a separate header row, replacing their unique containment arrows to basic blocks. All such facts remain in List. No relationship is inferred from names.

```text
Bounded GraphView -> stable node/edge ordering -> recorded compound hierarchy
    -> ELK layered layout (top to bottom, compact rows, crossing reduction)
    -> absolute card centers + orthogonal edge routes -> Cytoscape
```

ELK handles cycles without changing their recorded directions. A fixed random seed and stable identity ordering make placement independent of provider enumeration. NETWORK_SIMPLEX layering and LINEAR_SEGMENTS placement balance connected nodes without the former forced two-node layer bound. The dependency regression fixture owns a routing budget of at most three bends per edge on average, with no routes through unrelated card interiors. This bounds detours on that fixture, not arbitrary graphs or a proof of minimum crossings. Independent package scopes are laid out bottom-up and packed vertically, largest first, so the main package opens before smaller fixtures. Unrelated leaf cards use a regular grid whose column count uses their actual fixed presentation dimensions. Cross-boundary relations select a joint compound ELK calculation; they are never discarded to enable packing. Every leaf card has the same fixed 264-unit width, independent of kind, language, name, attributes or signature length. Property rows retain their separate compact-row contract above. Standard cards are 112 units high; callable and property heights follow their presentation contracts above. Text is measured and ellipsized inside that width rather than resizing nodes. Only compound frames expand to contain their children. Frames reserve header space. Layout routes use single-section ELK bend points for leaf endpoints, with eight-unit rounded corners confined to each bend neighborhood. Multi-section compound-boundary routes retain native curves. Dragging a node releases its incident routes to native curves so edges continue following the moved card. Theme and panel changes never rerun layout. Unchanged topology on live refresh retains manual positions and routes; changed topology is laid out again while retaining selection, pan and zoom. Query/snapshot/generation checks reject stale results.

ELK is the authority for automatic frame body rectangles. The renderer uses uniform 24-unit compound padding; directional padding aliases are not used. A 64-unit header and four-unit stroke clearance are reserved by the layout. After leaf positions are applied, frame minimum dimensions and their bias are computed bottom-up from actual rendered child bounds to reproduce the allocated rectangles. Automatic layout must separate every pair of non-ancestor rendered nodes, including frames, not just leaf cards. Stroke/selection changes must keep children out of the header. Frame header SVG spans the actual padded frame width, including its fill/dividers and leading language mark; it is not a fixed-width card image.

Manual node movement remains free. Moving a child preserves header clearance and regenerates resized ancestor header artwork without globally repacking manually positioned nodes. Theme and unchanged-topology refresh use current frame widths, so they cannot revert to a clipped fixed-width header. The full self-project fixture verifies rendered rectangle separation, parent/child clearance and header width agreement, including theme and selection changes.

A newly selected view fits only when that leaves cards readable (75–100%); larger graphs open at 75% aligned to the largest package frame (or the whole view when no package is present) and can be panned. Explicit Fit always shows the whole graph. Live workers retain one active calculation and the latest pending request, enforce 500-node/1500-edge bounds and terminate/recreate the nested ELK worker after a 10-second deadline. Errors are visible. Offline HTML embeds the same model and ELK and computes its bounded saved view without network requests.

## Destination-first interaction

The [navigation contracts](SPEC.md) govern every data-backed view change. A click commits one history entry and renders the destination title, target and Loading state synchronously. The foreground page yields a paint before beginning reads. A successful result replaces the pending entry; Back returns to the original selection and camera. Loading and failure clear the previous drawing, result badges and actions. Failure stays in the destination with Retry and Back. New navigation invalidates old requests and layouts. Refreshes of an unchanged current view retain the existing drawing.

The source Canvas toolbar offers Specification next to the view controls. It opens a scrollable reader in the central pane using the same snapshot-bound read as the Workspace Inspector. The action is visible even when the sidebar is closed or the workspace has no specification. While reading, the Canvas tools are hidden. The document is rendered as literal UTF-8 text, and the footer identifies the pinned snapshot. Index updates leave the open specification on its original snapshot.

Source selections expose Verify model directly in Inspector as well as the node menu. Verification screens distinguish preparing, confirmation, execution, published result and unavailable states. Results preserve exact snapshot, scope and source correspondence; an incomplete report remains incomplete when filtered or reopened. Published diagrams and condition accessories enter their destination before resolving source labels or session data. Extensions and model menus close immediately when their destination opens.

A pending imported session retains its identifier in browser history. In-tab retries retain their input reader without adding another history entry. A reload of a pending file or contribution without retained input reports that limitation and allows Back; it never fabricates an empty completed view or redispatches verification.

## Direct node verification

## Project verification

A C4 system/container menu exposes Verify project independently of Inspector and Open verification report. It enters the verification destination before availability reads. The screen presents subject, original snapshot, configuration and prepared action details. Run verification confirms the new action; returning to the view does not execute it. The menu action never opens an old report as a new execution result.

Explorer -> registered Invar verify-project action -> exact-snapshot execution -> project report contribution -> shared Canvas. Explorer owns this navigation and presentation; Invar owns planning, approved command execution and receipt validation. The result retains specification, implementation and source-correspondence assessments, including incomplete and unsupported obligations. No permanent node/Map button is added.

Schema-2 project contributions additionally carry five reviewed workflow gates. Canvas presents their declared nodes and return stage; missing, blocked or unreviewed gates keep the project verdict neutral rather than promoting scoped evidence to complete verification. Invar owns the evidence/review validation. Historical schema-1 artifacts remain readable as their original evidence projection; they are not converted into new reviewed workflow results.
